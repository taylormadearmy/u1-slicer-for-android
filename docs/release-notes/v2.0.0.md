# v2.0.0 — Filaments come from the file

## What's changed for you

In v1.x, slicing baked the choice of physical extruder slot (E1/E2/E3/E4)
into the saved G-code. Changing slot presets after the fact meant
re-slicing. The Prepare screen showed a mix of file-declared filaments
and slot preset colours, which made it easy to confuse "what the file
says" with "what's loaded in your printer".

v2.0.0 separates those two concerns:

- **Filament colours and material types come from the file.** When you
  load a 3MF, the canonical filament list embedded in the file (Bambu
  Studio / OrcaSlicer's `filament_colour` + `filament_settings_id`) is
  the source of truth. The Prepare screen shows exactly the colours and
  materials the file declares.
- **You can override colours and types on the Prepare screen.** If the
  file says "blue PLA" but you want to print "red PETG" instead, change
  it on Prepare. Your override drives the slice — the actual filament
  the slicer picks colours and temperatures for.
- **You map filaments to physical extruder slots at print time, not
  slice time.** When you tap *Send* / *Map & Print* / *Map & Upload*,
  a dialog asks which physical slot (E1/E2/E3/E4) each file filament
  should print from. The same sliced G-code can be sent to a printer
  with E1=red and a printer with E1=blue, without re-slicing.

In practice that means:
1. Slice once.
2. Decide slot mapping when you actually send to the printer.
3. Override colours/materials on Prepare if you want to print the file
   in different filaments than what its author chose.

## Bug fixes

### Buzz Lightyear plate 8 candy-cane stripes rendered blue instead of red
The Prepare 3D preview painted the stripes with the wrong colour. The
filament list, G-code preview, slice summary, and filament mapping
dialog were all correct — only the 3D mesh was wrong. Root cause was a
double-counting bug in the native paint-state segmentation; fixed in
the orcaslicer submodule and verified on Pixel 8a.

### Map & Print / Map & Upload silently did nothing
Tapping *Map & Print* or *Map & Upload* opened the Filament Mapping
dialog correctly and the dialog dismissed on Confirm, but the print
was never sent. No remapped G-code, no HTTP request, no error in
logs. Caused by a Compose coroutine scope tied to the dialog's
visibility — when the dialog closed, the IO coroutine that uploads
to the printer was silently cancelled before it could run. Fixed by
hoisting the scope to the parent composable so it survives the
dialog dismissal.

### Multi-plate UX clean-up (chip counts, dialog labels, summary)
For multi-plate Bambu files, the Slice Summary chip strip and the
Filament Mapping dialog now show exactly the filaments the slicer
actually used on the active plate, labelled by the file's canonical
filament index ("Filament 6", "Filament 10") rather than by compact
T-index. Border Collie, Buzz Lightyear plate 1, slip-slide-spin
plate 3, Shashibo plate 5 and flippy plate 4 (Hueforge) were the
test cases that drove the fix.

### SEMM painted preview colour mismatch (B58, GitHub #60)
Resolved by the v1.6.13 PaintColorDecoder fix and re-verified in
v2.0.0's full E2E batch on Pixel 8a. The `colored_3DBenchy` 4-colour
SEMM file now shows all 4 colour zones in the Prepare preview.

## Architectural changes (what's behind the UX)

If you're curious about how the change works under the hood:

- The native loader (OrcaSlicer's BBS importer) is now the single
  source of truth for what filaments a file uses. The Kotlin parsers
  that used to re-decode paint states, per-object extruders, and
  layer-tool data are retired (see [`docs/REFACTOR_STATUS.md`](../REFACTOR_STATUS.md)
  for the multi-phase refactor map).
- The slicer emits canonical T-indices in the saved G-code (T0..Tn
  where Tn is the n-th filament in the file's canonical list).
  Physical-slot mapping happens at Send time via a runtime remap.
- The Prepare 3D preview palette and the Filament Mapping dialog
  both index by canonical fileIndex, not by physical slot — so a
  file using filaments 3 and 10 shows up as "Filament 3" and
  "Filament 10" in the dialog, not "Filament 1" and "Filament 2".
