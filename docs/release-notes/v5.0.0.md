# v5.0.0 release notes

Version 5.0.0 adds profile-driven slicing and upload for supported rectangular-bed FDM printers while keeping the Snapmaker U1 as the default. The Add Printer dialog shows only the U1 until you enable **Experimental printer support**. The switch reveals Bambu LAN, Elegoo Centauri Carbon 1 beta, the pinned `taylormadearmy/OrcaSlicer` v2.2.4 catalogue, and `.orca_printer` import. The catalogue contains 326 models across 56 usable vendors, and the wizard shows the eligible subset after its geometry, physical-slot, and firmware checks.

The printer wizard resolves inherited Orca settings and validates the result before saving it. Each configured printer retains its profile and 1 to 4 physical slots. Cached profiles remain available offline. Generic printers can use Klipper or Marlin G-code with Moonraker, OctoPrint, or PrusaLink upload when the selected transport supports the operation.

Raw STL slices use the selected machine's bed dimensions and normalized start/end G-code, including Orca profiles such as Prusa CORE One that store custom G-code as one-element arrays.

The reconciliation preserves published v4.0.5 printer snapshots, schema-9 job fingerprints, CC1 transport, selected filament heating, and mapping-row fixes. The CC1 route is not Moonraker. Its protocol tests do not establish physical printer compatibility, and Carbon 2 remains unsupported. Relative-extrusion Marlin gets the required per-layer `G92 E0` reset. Generic independent tools require equal nozzle diameters; automatic shared-extruder multi-material designs remain blocked.

Existing Bambu support remains a separate experimental path. Version 5.0.0 does not add delta or circular beds, shared-extruder multi-material machines, SDCP or Duet transports, more than four physical extruders, or generalized ColorMix and Smart Paint mix encoding.

## Local candidate verification

This candidate is not published. The current evidence and remaining checks are recorded in [the reconciliation plan](../plans/v5-reconciliation.md).

The clean release APK reports version 5.0.0 and code 500. Its SHA-256 is `7B9880B41572C4C369EE9DAC01EE5FD4F89389365C764BA9DAA85A38EBEBAA83`.

The uncached JVM run passed all 2,235 tests across 249 suites, with no failures, errors, or skips. All 504 device methods passed in the fresh run: 493 independent tests and 11 mock-host or published-APK upgrade methods. The full independent suite recorded no failures or skips. Both upgrade sequences passed persistence checks after reinstall. All 37 E2E scenarios and 18 native checks against the actual release APK passed. Final restoration byte-verified all 24 original app files, and the app remains stopped.

The NDK 26 Release library keeps Clang 17.0.2 and all 64 JNI entry points. It now links the C++ runtime statically and uses 16 KB LOAD and GNU_RELRO alignment. Both APKs pass native packaging and manifest checks. Ten regression checks cover the alignment rules. The test phone uses a 4 KB kernel, so these results do not establish execution on a 16 KB kernel.

CC1 physical compatibility remains unverified. The authored-profile-marker submodule commit must also be available on its remote before publishing the source branch. No public tag or GitHub release is created by this reconciliation.
