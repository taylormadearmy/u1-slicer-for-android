# v4.0.5 review and validation

The release fixes oversized filament-assignment rows and stalled colour-mix remapping on large painted models. It also includes beta CC1 and imported single-nozzle Klipper support through Moonraker or OctoPrint.

Three independent reviewers examined the implementation, native changes, persistence, printer adapters, UI, and regression coverage. Accepted findings are fixed. Their final source rechecks found no remaining code blockers.

The review fixes cover these behaviours:

- Filament edits persist when a new single-nozzle printer has no stored preset yet.
- Generic slicing preserves selected material, nozzle temperature, bed temperature, and distinct first-layer temperature.
- Native generic G-code headers retain the values used by the slicer.
- OctoPrint requires a supported imported Klipper profile.
- Upload filenames satisfy the adapters' naming and length limits.
- Renaming a printer preserves its active connection and upload.

Device tests run on a Pixel 9a with Android 17 and 4 KB memory pages. Android Test Orchestrator runs each test in its own process. New regressions cover mapping-row layout, large painted-model remapping, generic native configuration, selected-filament propagation through the ViewModel, printer-edit validation, and saved-job migration.

The generic ViewModel regression checks executable `M109 S250` and `M190 S80` commands, plus the separate 245°C normal-layer and 250°C first-layer headers.

The native library is a stripped NDK 26 Release build with Clang 17.0.2. Its 64 JNI exports match the Kotlin declarations. The debug APK contains the same native binary as the checked-in library.

The complete JVM and device counts come from the test reports and runner inventory. The standard full-suite commands are `./gradlew testDebugUnitTest` and `./gradlew connectedDebugAndroidTest`. The full E2E runner is `scripts/run-batch-manual-e2e.ps1 -Suite Both -BambuTarget H2D`; this run selects all scenarios.

CC1 and OctoPrint protocol checks use mock servers. Physical uploads and printing on the new printer adapters remain unverified, so the adapters remain beta.

The first device sweep completed all 468 tests. Android's native-library compatibility warning obscured the two mapping-layout tests. Their setup now dismisses that specific system warning, and both passed on rerun with unchanged visibility assertions and unchanged application code.

Full 16 KB compatibility remains unverified. The JNI library has 16 KB ELF LOAD alignment, but the bundled C++ runtime has 4 KB alignment and the debug APK entries are not 16 KB aligned. This remains open as [native alignment issue #190](https://github.com/taylormadearmy/u1-slicer-for-android/issues/190).

The clean `assembleRelease --no-daemon` build passed, including release lint checks. The signed APK reports version 4.0.5 and code 405. Its native library matches the checked-in binary. The published `u1-slicer-orca-v4.0.5.apk` asset is 39,012,364 bytes, and GitHub's SHA-256 digest matches the local APK: `ec721a79d14a13e7f202d56f0eb3470d132fcfad79678eb912f12a55750bb979`.

The Pixel's original app data was restored after testing. Both settings stores and all six job files match their backup checksums. Exact database-row comparisons confirm the original three saved jobs and seven filament profiles. The app resumed the original completed 239-layer painted-model slice. No physical print was started.
