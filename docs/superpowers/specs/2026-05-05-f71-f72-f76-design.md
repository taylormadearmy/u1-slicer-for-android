## F72: Object skip UI

### Data model

New data class in `app/src/main/java/com/u1/slicer/`:

```kotlin
data class ExcludeObjectInfo(
    val name: String,
    val center: Pair<Float, Float>,          // mm, bed coordinates
    val polygon: List<Pair<Float, Float>>     // mm, bed coordinates; empty if not present
)
```

### Parsing

New file `app/src/main/java/com/u1/slicer/gcode/ExcludeObjectParser.kt` with a top-level function `parseExcludeObjects(gcodePath: String): List<ExcludeObjectInfo>`. Kept separate from `GcodeParser` since it is a single-pass header scan rather than a full move parse. Reads lines matching:

```
EXCLUDE_OBJECT_DEFINE NAME=<id> CENTER=<x>,<y> [POLYGON=[[x1,y1],[x2,y2],...]]
```

- `NAME` — required; everything after `NAME=` up to the next space
- `CENTER` — required; two floats
- `POLYGON` — optional; JSON-ish array of `[x,y]` pairs, parsed with a simple regex/split (no full JSON parser needed)

Called at slice completion in `SlicerViewModel.startSlicing`, immediately after G-code validation. Result stored as:

```kotlin
private val _excludeObjects = MutableStateFlow<List<ExcludeObjectInfo>>(emptyList())
val excludeObjects: StateFlow<List<ExcludeObjectInfo>> = _excludeObjects.asStateFlow()
```

Reset to `emptyList()` in `clearModel()`.

### ViewModel state (PrinterViewModel)

```kotlin
private val _skippedObjects = MutableStateFlow<Set<String>>(emptySet())
val skippedObjects: StateFlow<Set<String>> = _skippedObjects.asStateFlow()

fun skipObject(name: String) {
    viewModelScope.launch {
        repo.sendGcode("EXCLUDE_OBJECT NAME=$name")
        _skippedObjects.update { it + name }
    }
}
```

`_skippedObjects` resets to `emptySet()` when `PrinterRepository` detects a new print starting (existing `PrinterStatus.filename` change event).

### Cross-ViewModel data flow

`excludeObjects` lives on `SlicerViewModel`; the Printer screen composable uses `PrinterViewModel`. The parent composable (activity or nav host) observes `slicerViewModel.excludeObjects` and passes the collected list down to `PrinterScreen` as a plain `List<ExcludeObjectInfo>` parameter. This follows the existing pattern for cross-ViewModel data in this app — no direct ViewModel-to-ViewModel reference needed.

### UI — Printer screen

**Entry point:** A "Skip objects" `OutlinedButton` (with a grid/layers icon) added to the existing print controls row. Visible only when:
- Printer state is `printing` or `paused`
- `excludeObjects` list is non-empty

Tapping opens a `ModalBottomSheet`.

**Bottom sheet layout:**

```
┌─────────────────────────────────┐
│  Skip objects           [close] │
│                                 │
│  ┌─────────────────────────┐    │  ← Bed canvas (square, ~260dp)
│  │   [polygon outlines     │    │
│  │    on 270×270 bed]      │    │
│  └─────────────────────────┘    │
│                                 │
│  cube_1          [Exclude]      │  ← Text list
│  cube_2   ████████████████      │  ← Greyed = already skipped
│  cube_3          [Exclude]      │
└─────────────────────────────────┘
```

**Bed canvas (Compose `Canvas`):**
- Draws a light-grey bed background scaled to fit available width (square, 270×270mm → dp)
- For each object with `polygon`: draws outline path using `drawPath`, filled with semi-transparent grey when skipped
- For each object without `polygon` (only `CENTER`): draws a small circle at the centre point
- Each polygon/circle has a `Modifier.pointerInput` hit-test using the object's bounding box or polygon centroid with a minimum tap target of 48dp
- Tapping a non-skipped object calls `viewModel.skipObject(name)` and updates both canvas and list immediately
- Skipped objects: filled grey, no tap response

**Text list (below canvas, `LazyColumn`):**
- Each row: object name (truncated if needed) + "Exclude" `TextButton` (hidden/replaced with greyed "Skipped" label when already skipped)
- Tapping "Exclude" calls `viewModel.skipObject(name)`

Both sections observe the same `skippedObjects` StateFlow and update in sync.

### Tests

Unit tests in new `ExcludeObjectParserTest.kt` (`app/src/test/`):
- Parses `NAME`, `CENTER`, `POLYGON` correctly from a sample line
- Handles missing `POLYGON` gracefully (returns empty list for polygon field)
- Handles multiple `EXCLUDE_OBJECT_DEFINE` lines
- Returns empty list when no `EXCLUDE_OBJECT_DEFINE` lines present

## F76: Remove MakerWorld manual cookie UI

### What changes

**`SettingsScreen.kt`** — Remove:
- The entire manual cookie section (~L482–650): enable toggle, paste field, load/clear/copy buttons, `CookieInfoDialog` composable (~268 lines total)
- The `showCookieInfo` state variable and any `showMakerWorldModeInfo` state tied to the manual path

**`SettingsRepository.kt`** — Remove:
- `Keys.MAKERWORLD_COOKIES_ENABLED` DataStore key
- `makerWorldCookiesEnabled: Flow<Boolean>`
- `saveMakerWorldCookiesEnabled(enabled: Boolean)`

Keep `Keys.MAKERWORLD_COOKIES`, `makerWorldCookies: Flow<String>`, and `saveMakerWorldCookies(cookies: String)` — the browser still writes to these.

**`SlicerViewModel.kt`** — Remove:
- `makerWorldCookiesEnabled` StateFlow
- The `cookiesEnabled` read from `settingsRepo` in the download path
- Simplify the download cookie block to:

```kotlin
val cookies = MakerWorldUtils.sanitizeCookies(settingsRepo.makerWorldCookies.first())
// send Cookie header whenever non-empty
```

**`SettingsBackup.kt`** — Remove:
- `makerWorldCookies: String?` and `makerWorldCookiesEnabled: Boolean?` fields from `BackupData`
- Their serialisation in `export()` and deserialisation in `import()`

Session cookies expire; backing them up serves no purpose.

**`MakerWorldUtils.kt`** — Keep `hasAuthCookies` — still used by `MakerWorldBrowserScreen` to detect a successful login.

### Backwards compatibility

Old backup files carrying `makerWorldCookies` / `makerWorldCookiesEnabled` JSON keys must import without error. The existing `if (root.has("key"))` pattern already handles unknown keys gracefully — verify with an explicit regression test.

### Tests

**`SettingsBackupTest.kt`:**
- Remove: `round-trip preserves MakerWorld cookies` and `import without MakerWorld cookies returns null`
- Add: `import backup with legacy makerWorldCookies key does not throw` — constructs a JSON string with both legacy keys present, runs `import()`, asserts result is non-null and no exception thrown
